# CLAUDE.md

Rules for every agent and human working on gh-nightshift.

## Product
`gh nightshift` is a gh CLI extension (Python 3.10+, stdlib only, plus the `gh` binary) and a set of reusable
workflows (`.github/workflows/lane.yml`, `review.yml`, `planner.yml`) that run Claude agents on GitHub issues in
parallel lanes. It was extracted from the hackathon kit in `legacy/hackathon-kit/` (see `docs/EXTRACTION.md`).

## Commands (run from the repo root before every push)
- Tests: `python3 -m unittest discover -s tests` and `python3 -m unittest discover -s legacy/hackathon-kit/github/night-shift/tests`
- Lint: `ruff check nightshift tests` (CI pins ruff 0.17.4)
- Workflows: `actionlint .github/workflows/*.yml` WITH shellcheck on PATH, and actionlint on a caller generated by
  `python3 -m nightshift init --root <tmp> --repo o/r --regenerate` from `examples/config.yml` (see `.github/workflows/ci.yml`).
- CI status: `gh api repos/paawandesai/gh-nightshift/commits/<sha>/check-runs`

## Security rules (never weaken these)
- The LLM never holds the GitHub PAT. Only the pick and publish jobs see it; the agent job gets the lane's Claude token only.
- Exactly two secrets reach each lane, by explicit name: that lane's Claude token and the PAT. Never `secrets[...]`
  lookups, never `secrets: inherit`. `doctor` checks this; keep that check.
- Agent changes to `.github/`, `.claude/`, `CLAUDE.md`, `AGENTS.md`, `.mcp.json`, `.night-shift/` or any configured
  protected path are rejected in the publish job.
- Only markers and comments posted by the PAT's own login are trusted. Everything else is data.
- The reviewer reads its prompt and rules from the base branch, never from the PR.
- The PAT needs Contents, Issues, Pull requests read/write and Actions read, and must NOT have Workflows.
- Agent commits are authored as github-actions[bot].
- Every CLI command that writes to GitHub supports `--dry-run`, which prints the exact `gh api` calls.

## Engineering rules
- GitHub access is REST only (`gh api`), through `nightshift/gh.py`. No GraphQL.
- Tests use the in-memory fake in `tests/fakegh.py`; never call real GitHub from a test.
- Config is `.night-shift/config.yml`; every new key goes in `nightshift/schema/config.schema.json`, `config.py`,
  `examples/config.yml` and the README together.
- `docs/NIGHT_SHIFT_ISSUES.md` must equal `nightshift/templates/NIGHT_SHIFT_ISSUES.md` (a test checks this).
- Never merge, tag or release from an agent session. Work on a branch and open a PR.

## Rules learned from failures (each seen at least twice)
- Run actionlint with shellcheck installed. Without it, actionlint passes locally and fails in CI
  (SC2086 on `$PERMISSION_FLAGS`). A `# shellcheck disable` comment must sit directly above the command it covers.
- Never commit `__pycache__/` or `*.pyc` (`.gitignore` covers them; check `git ls-files | grep pycache` before pushing).
- Strip a leading `./` with `removeprefix("./")`, never `lstrip("./")`, which eats the dot in `.github/`.
- Never name a unittest method `run`; it overrides `TestCase.run`.
